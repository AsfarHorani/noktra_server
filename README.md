# Job Tracker — Server

Django API backend for [Job Tracker](https://github.com/AsfarHorani/noktra_extension) — a Chrome extension that automatically detects job postings, tracks applications, and uses a locally-run LLM to generate cover letters, interview prep answers, and job-search insights.

This repo is the backend half of a two-repo project. The extension + dashboard client lives in a companion repo: **[noktra_extension](https://github.com/AsfarHorani/noktra_extension)**.

Everything here runs **entirely on your own machine** — there's no hosted deployment, no cloud database, and no third-party AI API. Application data lives in a local SQLite database, and every AI feature (cover letters, interview answers, resume parsing, job-search insights) is generated by a locally-run [Ollama](https://ollama.com) model. Nothing about a user's job search or resume ever leaves their computer.

## What it does

- **Auth** — real per-user signup/login (hand-rolled token auth, not a shared password), scoping every other endpoint to `request.user`.
- **Applications** — full CRUD for tracked job applications (title, company, status, notes, job description, cover letter, ...), plus a dedup lookup keyed by a `jobKey` the extension computes per posting.
- **Profile** — a structured candidate profile (work history, skills, education, projects, certifications) that the AI features draw on.
- **AI Insights** (`analysis` app) — compares applications that led to an interview/offer against ones that were rejected/ghosted and surfaces qualitative, evidence-based patterns. Deliberately never asks the LLM to count or compute a rate — see [`analysis/stats.py`](analysis/stats.py); the model only describes differences between two pre-computed groups.
- **AI Assistant** (`assistant` app) — parses an uploaded resume into a structured profile, and generates tailored cover letters / interview-answer drafts from a candidate's real profile + a specific job's description. Cover-letter generation is hard-blocked (400, before ever calling the model) if either the candidate profile or the job description is missing — a generated result with nothing real to draw from is worse than no result at all.

## Tech stack

- **Django 5** — plain views (`JsonResponse`, `@csrf_exempt` + a hand-rolled `Authorization: Token <key>` auth decorator), deliberately **not** Django REST Framework. This project stays dependency-light on purpose; a handful of plain views and one auth decorator covers everything actually needed here.
- **SQLite** — one file, zero setup. This server is designed to run locally alongside the extension, never deployed, so there's no case for a separate DB service.
- **Ollama** — local LLM inference for every AI feature, called via a thin `requests`-based client (`analysis/ollama_client.py`). No OpenAI/Anthropic/cloud API key required or supported today.

## Getting started

### Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com) installed and running, with a model pulled (default `llama3.1:8b`; any model matching your machine works too, see [Configuration](#configuration))

### Setup

```bash
git clone https://github.com/AsfarHorani/noktra_server.git
cd noktra_server

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env             # optional — see Configuration below
python manage.py migrate
python manage.py runserver 8000
```

In a separate terminal, make sure Ollama is running with the model pulled:

```bash
ollama serve
ollama pull llama3.1:8b
```

The API is now listening at `http://127.0.0.1:8000/api/`. Point the [extension](https://github.com/AsfarHorani/noktra_extension) at it and sign up for an account from the popup or dashboard — everything else (tracking, AI features) works from there.

### Running tests

```bash
python manage.py test
```

63 tests across all four apps (`accounts`, `tracker`, `analysis`, `assistant`), including explicit per-user data-isolation tests (user A can never read/edit/delete user B's data) and mocked-Ollama coverage for every AI endpoint — the suite runs in well under a second with no live Ollama instance required.

### Manual end-to-end testing against a live model

`test_payloads/*.json` are hand-crafted fixtures for exercising the `/api/analyze/` endpoint against a real running Ollama (the automated suite mocks the model call, so it can't tell you whether the actual generated text is any good):

```bash
# Get a token first:
curl -X POST http://127.0.0.1:8000/api/auth/signup/ \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"a-real-password"}'

curl -X POST http://127.0.0.1:8000/api/analyze/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Token <token-from-above>" \
  -d @test_payloads/mixed.json
```

## Configuration

Copy `.env.example` to `.env` and fill in what you need — every value has a safe local-dev default, so `.env` is entirely optional unless you want to change one of these:

| Variable | Default | Purpose |
|---|---|---|
| `SECRET_KEY` | an insecure placeholder | Django's signing key. Generate a real one for anything beyond throwaway local dev — see the comment in `.env.example`. |
| `DEBUG` | `True` | Django debug mode. |
| `ALLOWED_HOSTS` | `127.0.0.1,localhost` | Comma-separated. This server is designed to run locally only. |
| `OLLAMA_URL` | `http://localhost:11434` | Where to reach Ollama's REST API. |
| `OLLAMA_MODEL` | `llama3.1:8b` | Which pulled model to use for generation. Swapping models needs no code change. |

## Project structure

```
jobtracker_server/   Django project settings/urls
accounts/            Signup/login/logout, token auth (AuthToken model, require_auth decorator)
tracker/             Application/Profile/UserSettings CRUD, camelCase<->snake_case serializers
analysis/            Job-search insights — deterministic stats + qualitative LLM comparison
assistant/           Resume parsing, cover letter & interview answer generation
SCHEMA.md            Entity-relationship diagram for the full data model
test_payloads/       Fixtures for manual testing against a live Ollama
```

Each app has its own `tests.py`; `analysis`/`assistant`'s prompt wording lives in a `prompts.json` alongside their `prompts.py` (see either file's module docstring) so tuning a prompt never requires touching Python logic.

See [SCHEMA.md](SCHEMA.md) for the full data model.

## Security notes

- This server has no rate limiting, no email verification, and no password-reset flow. It's designed for single-user local use alongside the browser extension, not as a public-facing service — don't expose it to the internet as-is.
- `.env` is gitignored. Never commit real secrets; `.env.example` documents every variable with safe placeholder values.
